# 一键缴费集成

基于 https://github.com/UWPBOOM/NTU_EcoCheck 的 `d88044b` 开发。

## 使用

1. 在首页填写统一身份认证账号和密码，选择校区、楼栋、房间。
2. 点击“一键查询”旁边的“一键缴费”，先阅读“缴费使用提示”，点击“已了解，继续缴费”后才校验配置并打开缴费入口；点击取消、返回或关闭弹窗则停留在首页。
3. 应用打开学校官方入口 https://pay.ntu.edu.cn/showPublic ，自动进入“学生宿舍电费”。需要登录时，使用首页账号填写学校的账号密码表单，由官方脚本完成密码加密和提交。
4. 应用按顺序选择校区、楼栋和房间；完成后停止自动操作。
5. 核对官方页面中的宿舍信息，手动填写金额并确认付款。支付结果以官方订单状态为准。

“一键查询”恢复原版居中弹窗、五步进度、结果卡片和动画：从原查询入口进入学校认证，选择本次校区、楼栋、房间，读取电量并保存历史。查询不显示缴费表单或支付按钮。需要滑块验证或手动登录时，显示完整大小的学校登录页和提示；登录错误显示官方错误文字，应用不自动重复提交。完成认证后继续查询。查询失败或超时弹出具体提示。

遇到验证码、登录错误、页面变化或信息不匹配，可直接在可见网页中操作。顶部“手动操作”可随时停止填写；刷新图标重新打开缴费入口。页面支持双指缩放。

1.0.2 修正手机排版：学校缴费页的多列、嵌套表格按字段纵向排列，电量数字不逐字断行，金额输入框至少 44px 高。顶部“原网页 / 手机排版”可在同一页面切换，不刷新、不清空金额。软键盘出现时为输入区留出空间。认证页面的滑块节点不做表格重排或尺寸修改。

出现二维码后，可点击底部“识别并打开支付”。二维码只在本机从已加载图片、Canvas 和当前网页画面读取，不上传截图或支付链接：

- 优先读取可见二维码的图像像素，并使用 [Android PixelCopy](https://developer.android.com/reference/android/view/PixelCopy) 读取当前 WebView 在应用窗口中的实际显示区域。跨域图片无法由网页 Canvas 导出时，使用窗口画面路径；不再依赖可能空白的 `WebView.draw(Bitmap Canvas)`。读取超时、失败、页面切换和多个支付码均有单独处理。

- 学校提供微信 H5、微信支付跳转链接或支付宝支付链接时，尝试用原链接继续支付；打开应用前仍需用户确认。能否进入收银台取决于学校渠道、订单及支付应用。
- 用户提供的微信、支付宝截图已通过与应用相同的解码器分别识别为微信 Native 支付码和支付宝支付码。微信 Native 码提供“保存并打开微信”，随后在微信扫一扫中从相册选择支付码。支付宝优先使用原码链接打开对应应用；无法打开时提供保存后扫描。打开应用首页不代表直接调起支付收银台。
- 不将微信扫码订单拼装成 H5 订单，也不把微信订单转换成支付宝订单。支付宝需由学校提供相应支付渠道。
- Android 10 及以上直接将用户选择保存的支付码写入相册，不申请相册读取权限；Android 8/9 使用系统文件保存窗口。应用不发送图片给联系人。
- 页面存在多个不同支付码时，要求放大目标二维码后重试，避免自动选择错误订单。二维码有效期和付款结果仍以官方页面为准。

关于不同支付方式的官方流程，参见 [微信 Native 扫码支付](https://pay.wechatpay.cn/doc/v3/merchant/4012525171) 和 [微信 H5 支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791831)。

## 为什么直接打开学校页面

用户确认的今日校园服务入口就是 `https://pay.ntu.edu.cn/showPublic`。原项目使用同一站点的 `schoolid`、`building`、`room` 字段查询电量，因此可以直接复用已有宿舍数据和 WebView 登录 Cookie。

对提供的今日校园 APK 的静态检查确认包名为 `com.wisedu.cpdaily`，注册了 `campusnextins` Scheme；APK 有加固，未确认该 Scheme 打开指定缴费服务的参数，不能据此声称支持跨应用自动填写。当前实现通过学校官方网页完成集成。

## 实现范围

- 首页两个按钮共用当前表单，进入缴费时固定本次宿舍配置。
- 新缴费浏览器与查询 WebView 在同一应用内共享 CookieManager，不读取今日校园的数据。
- 自动填写仅在精确匹配的学校 HTTPS 域名执行；账号密码只注入 `authserver.ntu.edu.cn` 的账号密码表单。
- 学校入口目前返回 HTTP 认证跳转；已验证对应 HTTPS 入口可访问，新增流程将学校主框架的 HTTP 导航升级为 HTTPS。
- 新流程没有 JavaScript 原生桥接，不把账号密码放进 URL、导航参数或日志。
- 宿舍选择同时检查 ID 和名称，等待联动选项加载；缺失或不一致时停止。完成后不再覆盖用户的选择。
- 查询弹窗和缴费页面分开，复用官方浏览器控制器与登录保护。正常查询的卡片、步骤、结果和动画取自原版 UI；查询文档不注入缴费排版，沿用原版 `td#zhye` 电量读取方式并兼容单位、标签和后台请求。查询浏览器保持完整布局大小，仅在需要登录验证时可见和可交互。自动流程超时为 60 秒；等待用户登录验证时暂停超时。
- 每个账号 10 分钟内最多允许一次自动登录提交。原生控制器先将保护记录同步保存，再向当前登录文档发放一次性提交许可；JS 未拿到许可不会点击登录。页面更新后旧许可失效。
- 滑块、验证码或登录错误一旦出现，该文档停止自动提交。刷新、关闭重开、查询与缴费切换、进程重建都不会立即重置自动提交预算；用户随时可以在官方页面手动登录。保护的是本应用的自动操作，并不解除学校服务器已经产生的账号冻结。
- 自动流程不填写金额，不创建订单，不点击付款或支付成功按钮。
- 官方网页的用户操作弹窗保留在同一 Cookie 会话中；支付宝、微信只通过限定包名的全新 Intent 打开。
- 新增浏览器关闭时停止轮询并释放 WebView；系统重建应用后不恢复未完成的付款操作。

## 真机验收

Debug 测试包包名为 `com.ntu.electricity.payment`，与原版共存，名称为“NTU电费查询·缴费测试”。原版的保存数据不会自动迁入，首次需重新填写。

验收时检查：两个按钮并排显示；查询仍可用；缴费能完成学校登录和宿舍联动；金额为空且需用户确认；验证码可手动处理；能返回与关闭页面；支付方式和订单状态以学校页面为准。付款前应核对房间。

1.0.4 查询回归验收：点“一键查询”应看到原版暗色遮罩和“NTU 电费查询”居中弹窗，含五步进度；完成后展示原版“查询完成 / X 度 / 宿舍 / 时间 / 确定”，历史页新增该记录。需要验证时手动完成学校登录，随后继续查询；登录错误时应看到实际错误信息。关闭查询后点“一键缴费”，仍进入缴费页。

开发过程未使用真实学生账户，也未创建真实支付订单。登录后的电费页面和最终付款链路仍需用户在手机上验证。
